# 搜狗微信搜索匹配逻辑说明

> 适用文件：`scripts/fetch_wechat.py`（`parse_results()` 归属过滤）
> 更新日期：2026-08-13
> 一句话结论：**不是精确匹配，而是「搜狗全文关键词检索 + 脚本侧双向子串包含过滤」的两层宽松匹配**。

---

## 一、整体匹配链路

```
accounts.json 账号名
    │
    ▼
① 搜狗检索：weixin.sogou.com/weixin?type=2&ie=utf8&query={账号名}
    │   （全文关键词检索，按相关度排序，返回"该账号文章 + 提到该名字的其他账号文章"）
    ▼
② 脚本侧归属过滤：双向子串包含
    │   （account in src_account 或 src_account in account）
    ▼
③ 时间窗口过滤：publishedAt >= since_ts（近 N 天，滚动窗口）
    │
    ▼
④ 数量截断：per_account 条（凑满即 break，默认 3）
```

## 二、第一层：搜狗自身的检索语义

- **请求形式**：`https://weixin.sogou.com/weixin?type=2&ie=utf8&query={账号名}`
- `type=2` 是**文章搜索**，账号名被当作**全文检索关键词**，而非账号 ID。
- 返回结果包括：
  - 该账号发布的文章；
  - **任何标题/正文中"提到这个关键词"的其他账号文章**。
- 按**相关度排序**，不保证时间序（`tsn` 时间过滤参数实测无效）。
- 这一层与"精确匹配账号"完全无关，本质是搜索引擎行为。

## 三、第二层：脚本侧归属过滤（双向子串包含）

代码位置：`scripts/fetch_wechat.py` → `parse_results()`（L109-113）

```python
ma = RE_ACCOUNT.search(block)
src_account = html.unescape(RE_STRIP_TAG.sub("", ma.group(1)).strip()) if ma else ""
# 归属过滤：搜索「机器之心」可能混入提到该名的其他账号文章
if src_account and account not in src_account and src_account not in account:
    continue
```

保留条件（满足其一即可）：

| 条件 | 含义 | 示例 |
|---|---|---|
| `account in src_account` | 搜索词是结果账号名的子串 | 搜「智谱AI」命中"智谱AI研究院" → 保留 |
| `src_account in account` | 结果账号名是搜索词的子串 | 搜「月之暗面Kimi」命中"月之暗面" → 保留 |
| `src_account` 为空 | **直接放行，不过滤** | 解析不到账号归属的条目有污染风险 |

> 注意：这是**双向子串包含**，不是 `==` 精确相等。

## 四、后续两层过滤

| 过滤 | 实现 | 说明 |
|---|---|---|
| 时间窗口 | `ts < since_ts → continue` | 滚动 N 天（默认 7 天）；遍历全页不提前 break（相关度排序下旧文在前） |
| 数量截断 | `len(out) >= per_account → break` | 每账号默认 3 条；高频账号易被快讯类内容占满配额 |

## 五、实测案例

### 案例 1：正常情形（机器之心）

搜「机器之心」第一页 9 条，解析后全部归属"公众号：机器之心"，过滤正确放行。头部账号收录干净时命中质量高。

### 案例 2：污染情形（十字路口）

搜「十字路口」返回的是 **2018 年时政旧号**的文章。该旧号名称恰好是"十字路口"，双向子串包含天然命中，脚本**无法区分同名不同号**。该账号已从 `accounts.json` 移除。

### 案例 3：动态变化（数字生命卡兹克）

同一账号两次探测，第一页结果不同（收录更新/排序调整）：8/12 时第一页含 8/6 文章，8/13 时第一页含 8/7、8/12 文章。**搜狗收录与排序是动态的**，第一页内容会漂移。

## 六、匹配风险清单

| 情形 | 结果 | 应对 |
|---|---|---|
| 账号名唯一、搜狗收录好（机器之心） | 命中干净 ✅ | — |
| 结果混入"提到该名字"的他人文章 | 被子串过滤正确剔除 ✅ | — |
| **同名不同号**（十字路口案例） | 无法识别，抓取污染 ❌ | 入清单前探测验证；持续 0 归属则移除 |
| **子串包含误纳**（搜"AI科技评论"命中"AI科技评论员"） | 抓取污染 ❌ | 名称尽量取官方全名 |
| **src_account 解析为空** | 直接放行，可能污染 ❌ | 关注抓取日志中空归属条目 |
| **搜索词与官方号名互不包含**（搜"Kimi"但号名是"月之暗面"） | 误过滤，漏抓 ❌ | 用官方账号全名，如「月之暗面Kimi」 |

## 八、最佳实践：新账号入清单前的前置验证

1. 用 `fetch_wechat.py` 的搜索逻辑逐个探测候选名；
2. 检查第一页解析结果的 `source` 归属是否与目标账号一致；
3. 检查文章主题是否相关（排除同名无关旧号）；
4. 无法确认归属或连续 0 结果时，标记「需改名/移除」。

> 一句话总结：**名字取得越准确、越独特，抓得越干净；名字含糊或与他人号名相近，就会出现污染或漏抓。**
